A plain-English project recap

FieldForge

A local customer-data onboarding platform that turns messy records into trusted tables, visible exceptions, reconciled business metrics, and a dashboard a customer team can operate.

The project in one picture

6 messy sources→ Profile→ Validate→ Accept or quarantine→ Match customers→ Build trusted models→ Dashboard + evidence

What we built

10,163default source rows

Customers, subscriptions, invoices, orders, order lines, and support tickets.

29bad records quarantined

Nothing silently disappeared; every rejected record carries a reason.

119/119dbt nodes passing

18 models and 101 data tests, plus Python and reconciliation gates.

Trusted data layer

Bronze preserves incoming evidence. Silver contains validated records. Gold contains customer, revenue, product, date, subscription, support, and order-integrity models.

Operational experience

The dashboard shows KPIs and quality problems. SQL Lab exposes small real tables so decisions and lessons use the project’s actual data.

Reproducible delivery

The same seeded inputs produce the same outputs. A full dependency lock and clean-clone test prove another engineer can rebuild it.

Scale and runtime evidence

The 10× profile processed 102,479 rows. PySpark matched all 1,494 accepted orders with zero missing or unexpected IDs.

What you contributed

You did not write much code in the latest workflows. Your contribution was product ownership and data-governance judgment—important work, but different from hands-on implementation.

You protected event evidence. You reasoned that an event cannot happen before the company knows the customer, and decided the CRM created_at value—not the event date—was wrong.
You chose the investigation story. You asked us to emphasize the known quarantined-line case instead of presenting two unexplained order gaps as if they were solved.
You selected meaningful scale. You chose the 10× / 5,000-customer benchmark after seeing the real 500-customer baseline.
You set delivery discipline. You required milestone commits, pushes only for major progress, work on the SSD branch, no merge to main, and no public release without approval.
You corrected the coaching process. You noticed when implementation had replaced learning and required the learner-in-the-loop agreement to be restored.
